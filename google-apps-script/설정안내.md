# Google 시트 연동 설정

앱은 브라우저에서 Google 시트에 직접 접근하지 않고, Next.js 서버를 거쳐 Apps Script 웹 앱과 통신합니다. Apps Script URL은 서버 환경 변수에만 저장합니다.

## 1. Apps Script 코드 배포

1. 대상 스프레드시트에서 **확장 프로그램 → Apps Script**를 엽니다.
2. 편집기의 `Code.gs` 내용을 이 폴더의 [Code.gs](./Code.gs) 코드로 교체하고 저장합니다.
3. 스프레드시트 첫 번째 탭의 첫 행에 다음 열 제목을 입력합니다. 첫 행이 비어 있으면 첫 요청 때 코드가 자동으로 입력합니다.

   `timestamp`, `datetime`, `category`, `content`, `color`, `state`, `order`

4. **배포 → 새 배포 → 웹 앱**을 선택합니다.
5. 실행 사용자는 본인 계정, 액세스 권한은 앱을 사용할 사용자에 맞게 선택하고 배포합니다. 첫 실행 때 스프레드시트 접근을 승인합니다.
6. 발급된 웹 앱 URL을 복사합니다. URL은 보통 `/exec`로 끝납니다.

코드는 전달받은 스프레드시트 ID의 첫 번째 탭을 사용합니다. 열은 첫 행의 제목으로 찾으므로 열 순서는 달라도 됩니다. 기존 내용이 있는 탭은 필요한 일곱 제목이 모두 있어야 합니다.

## 2. Next.js에 URL 등록

프로젝트 루트에 `.env.local` 파일을 만들고 다음을 입력합니다.

```dotenv
NEXT_PUBLIC_GOOGLE_SCRIPT_URL=https://script.google.com/macros/s/배포_ID/exec
```

개발 서버를 다시 시작하면 앱이 시트에서 메모를 불러옵니다. 추가·편집·삭제·완료 표시·순서 변경은 시트에 저장되고, 시트 연결이 설정되지 않은 동안은 기존처럼 브라우저 저장소를 사용합니다. 기존 `.env.local`에 `NEXT_PUBLIC_GOOGLE_SCRIPT_URL`이 설정되어 있다면 그 값을 그대로 사용합니다.

## 열 데이터

| 열 | 저장 내용 |
| --- | --- |
| `timestamp` | 시트 기록 날짜와 시간. 각 메모를 식별하는 고유 키로도 사용 |
| `datetime` | 메모 생성 날짜와 시간 |
| `category` | `할 일`, `아이디어`, `기타` |
| `content` | 메모 내용 |
| `color` | `yellow`, `pink`, `green`, `blue` |
| `state` | 미완료는 `진행 중`, 완료 체크 시 `완료` |
| `order` | 보드에 표시할 순서 |

> 웹 앱을 공개 액세스로 배포하면 URL을 아는 사람이 스프레드시트를 변경할 수 있습니다. 가능한 경우 앱을 사용할 Google 계정으로 접근을 제한하고, URL을 공개 저장소에 올리지 마세요.
